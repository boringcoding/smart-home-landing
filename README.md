# Smart House Business

Интерактивный шоурум умного дома на React, TypeScript и Three.js, подготовленный из предоставленного `first.ifc`. Это самостоятельный проект: существующего сайта не было.

**Шторы управляют пятью окнами в трёх комнатах.** Гостиная с кухней содержит три окна, обе спальни — по одному. Окно санузла имеет матовое стекло и не оборудовано шторами. Для всех пяти помещений подготовлены отделка и потолки; архитектура дома доступна снаружи, на раскрытом этаже и изнутри комнат. Остальные умные системы демонстрируются в гостиной и входной зоне. Добавленные устройства, отделка, трассы и названия комнат — проектное предложение. Полная приёмка исходного ТЗ не заявляется: статус каждого критерия приведён в [docs/acceptance.md](docs/acceptance.md), проверка новой геометрии и интерфейса — в [протоколе QA](docs/qa-report.md).

## Быстрый запуск

Нужен Node.js 22.12+ либо 24+ и npm. Архитектура уже экспортирована, для просмотра Blender и Python не требуются.

```sh
cd smart-house-business
npm ci
npm run dev
```

Откройте `http://127.0.0.1:5173`. Команда разработки запускает интерфейс Vite и локальный сервер заявок на `127.0.0.1:4174`. Сервер доступен только на этом компьютере. На macOS можно открыть `Start.command`: он открывает уже запущенное демо либо устанавливает npm-зависимости, если их ещё нет, запускает проект и открывает браузер после готовности сервера.

Сборка и запуск готовой версии:

```sh
npm run build
npm start
```

Готовая версия и локальная форма доступны на `http://127.0.0.1:4174`. Команда `npm start` требует предварительно созданную папку `dist`. Остановка — `Ctrl+C` в терминале. Если порт занят, сначала завершите предыдущий экземпляр проекта.

Открывать `index.html` двойным нажатием не следует: загрузка GLB, реестра и модулей требует HTTP-сервера.

## Статическая версия для GitHub Pages

Для размещения в подпапке репозитория `smart-home-landing` сборка использует два параметра:

```sh
VITE_STATIC_HOSTING=true VITE_BASE_PATH=/smart-home-landing/ npm run build
```

Публикуется содержимое `dist`. `VITE_BASE_PATH` задаёт префикс для скриптов, реестра и 3D-ресурсов; для сайта в корне домена используйте `/`. Сборка статического режима не запускает локальный сервер Node.js.

В этом режиме нет `/api/leads` и серверной формы `/request`. Интерфейс сохраняет черновик в браузере и предлагает скачать заявку с контактами либо отдельный JSON комплектации без контактов. Кнопка «Сохранить на локальном сервере» заменена на «Скачать комплектацию JSON»; запрос к API не выполняется и успешная отправка заявки не имитируется. Без JavaScript статическая страница показывает пояснение вместо ссылки на отсутствующую серверную форму.

Для локальной версии запускайте обычные `npm run build` и `npm start` без `VITE_STATIC_HOSTING=true`: запись заявок локальным сервером остаётся доступна. Флаг задаётся во время сборки, поэтому для смены режима нужен новый `dist`.

## Как пользоваться

- «Дом» показывает оболочку и крышу, «Этаж» раскрывает помещения, «Внутри» позволяет осмотреть отделку и потолок выбранной комнаты, «Инженерия» показывает предлагаемые трассы. Комнаты выбираются кнопками, списком или стрелками. «Вернуть ракурс» восстанавливает вид, «Дом целиком» возвращает общий обзор; состояние систем сохраняется.
- Вращение — перетаскивание, приближение — колесо мыши или жест двумя пальцами. На canvas с клавиатурным фокусом работают стрелки, `+`, `-`, `Home`. Кнопка в правом верхнем углу сцены скрывает панели.
- Сценарии «Утро», «Ушёл», «Вернулся», «Кино», «Ночь» меняют только включённые в комплектацию функции. Новая команда начинает движение из фактического положения механизма.
- В панели доступны четыре группы света, температура света, движение и остановка штор, уставка отопления, протечка и отказ клапана, режимы охраны, сигналы датчиков, экран и демозвук.
- Проценты штор обозначают степень **закрытия**: 0% — полностью открыты. Проценты клапана обозначают степень **открытия**: 0% — вода перекрыта.
- На вкладке штор «Эта комната» меняет положение одной группы, «Весь дом» — всех включённых помещений со шторами. Два мягких полотна панорамы и пара обычных штор бокового окна гостиной отображаются по общей команде; каждая спальня независима. У панорамы верх закреплён по скатам, ткань собирается к ручным боковым подхватам: анимация показывает положение, электропривод для этого решения не предусмотрен. Общая панель показывает среднее и значения трёх комнат. «Стоп» и реверс сохраняют положение. В санузле матовое стекло без штор; в прихожей окна нет.
- Температура меняется в ускоренной модели; это не расчёт отопления. Переключатели двери и окна имитируют датчики: исходные створки не имеют добавленного электропривода.
- «Посмотреть под мойкой» открывает осмотр крана внутри тумбы кухонной мойки из IFC. Протечка проходит последовательность «вода → датчик → закрытие клапана → остановка притока». Лужа и источник протечки сохраняются после перекрытия; если закрыть и открыть кран до срабатывания датчика, приток возобновится. Авария блокирует открытие, неисправный клапан не изображается успешно закрытым. «Сбросить протечку» очищает только водный опыт, сохраняя остальные устройства, комплектацию и сценарий. Это сброс демонстрации, не ремонт оборудования. Общий «Сбросить демо» возвращает все устройства к начальному состоянию.
- В «Моей комплектации» выбираются системы, помещения и дополнительное перекрытие воды при уходе. Исключённые шторы останавливаются; возвращение комнаты в комплектацию не возобновляет старую команду. «Утро», «Ушёл», «Вернулся» и «Ночь» учитывают все выбранные комнаты со шторами; «Кино» управляет только гостиной. Старый сохранённый выбор санузла не включает там шторы. Выбор спальни не добавляет в неё остальные умные системы.
- В «О демонстрации и 3D-сцене» находятся качество, уменьшенное движение, дневной свет, журнал и показатели текущей сессии. Эти показатели не подтверждают результаты на других устройствах.

Подробное управление комнатами, режимами камеры, шторами и заявкой описано в [docs/ui-guide.md](docs/ui-guide.md).

## Отделка и внешний вид

- Пол гостиной, спален и прихожей — интерпретация образца **ROYCE Sense SE-710 «Дуб Айа»**, модули 180×1200 мм. Карта древесины имеет масштаб UV 0,78×2,1 м: доски получают разные фрагменты с воспроизводимым случайным смещением и четыре близких оттенка, чтобы рисунок не повторялся целиком на каждой планке. В санузле — матовый керамогранит по образцу **LAPARET Smart Gris**, модули 600×600 мм с швом 3 мм.
- Внутренняя обшивка — вертикальная белёная древесина с шагом 14 см и геометрическими пазами 2 мм; исходные проёмы сохранены. В душевой Smart Gris покрывает стены и пол; стены санузла вне душевой остаются в вагонке. Внутренние двери имеют светлую древесную отделку.
- Матовый белый потолок гостиной повторяет скаты кровли с отступом около 10 см. В остальных четырёх комнатах потолки плоские, на отметке 2,38 м. У обычных окон предусмотрены геометрические ниши со скрытыми карнизами. Потолки и встроенные светильники имеют категорию `ceiling`: в режиме «Этаж» они скрыты, в режиме «Внутри» видны.
- На пять окон IFC предусмотрено **8 полотен**: два мягких тканевых полотна панорамы с неподвижным наклонным верхом и ручными боковыми подхватами, а также три обычные пары — на боковом окне гостиной и в спальнях. Шестое окно, в санузле, сохранено с матовым стеклом без штор, карниза и механизма управления.
- Напольный торшер, растение и две диванные подушки удалены из видимой сцены. Стол и четыре стула белые; телевизор один. Локальный свет представлен подсветкой мойки.
- Доски террасы повёрнуты на 90° относительно прежней раскладки и идут вдоль фасада: ширина 14 см, сквозные зазоры 1 см. Каждая из пяти уникальных ступеней собрана из двух досок. Нижний край правого фасада выровнен на −0,43 м без локальной выемки; ниже сохранён отдельный утопленный цоколь. Обе передние секции под настилом и угловые возвраты закрыты 12 коричневыми фасадными досками, проём лестницы свободен. У 24 цокольных реек устранены ложные швы текстуры, четыре подложки сделаны матовыми графитными. Все восемь сегментов дождевых цепей удалены из видимой сцены и обоих GLB; исходники сохранены в скрытом архиве мастера вместе с заменёнными слоями и сваями. Подробности и проверка сохранности окон — в [docs/east-base-correction.json](docs/east-base-correction.json).
- Земля визуально совмещена с нижней ступенью: низ ступени −0,914 м, поверхность земли −0,924 м. Это решение для изображения, а не проект фундамента или вертикальной планировки.
- Фасад, терраса и лестница используют приглушённое коричневое дерево; соответствующие металлические элементы — графит по предоставленному фото. Назначения материалов привязаны к исходным GUID.

Панорамные шторы показывают проект мягкого текстильного оформления с ручными подхватами. Верхние крепления следуют скатам и остаются неподвижными; боковая сборка ткани демонстрируется морфом. Пошив, крепления и размеры подхватов требуют обмера и согласования с изготовителем. Модель не является рабочим чертежом или обещанием автоматического привода панорамы.

Параметры и архивирование записываются генератором в [docs/interior-finishes.json](docs/interior-finishes.json). Новые текстуры древесины, керамогранита и белёной обшивки созданы встроенным `image_gen`; образцы пола и общий вид предоставлены пользователем. Это визуальная интерпретация фотографий и описания, без заявления точного цветового совпадения или использования официальных карт производителя. Промпты сохранены в [docs/material-prompts.json](docs/material-prompts.json) и [docs/lining-material-prompt.txt](docs/lining-material-prompt.txt). Происхождение фотографий и ресурсов указано в [реестре лицензий](docs/licenses.json); предоставление фото не объявляется подтверждением прав на их публичную перепубликацию.

## Заявка и данные

Выбранная комплектация сохраняется в `localStorage`. Форма создаёт **черновик в текущем браузере**, который можно скачать как JSON. Контакты не отправляются автоматически. Следующее отдельное действие — «Сохранить на локальном сервере» — вызывает `POST /api/leads`; успех показывается только после подтверждённой записи файла в `data/leads/*.json`.

Локальный сервер не отправляет письма, сообщения, заявки в CRM или отдел продаж. Публичная доставка заявок, стоимость оборудования, аналитика и авторизация не настроены. Локальная форма без зависимости от 3D доступна по `/request` только при запуске Node.js-сервера; в статической версии Pages её нет. Кнопка «Очистить черновик» в форме и на экране результата удаляет `smart-house.request.v1` и очищает контакты в интерфейсе, сохраняя комплектацию. Если браузер запрещает удаление, интерфейс показывает ошибку и не утверждает, что данные удалены. Эта кнопка не удаляет ранее записанные файлы `data/leads` и скачанные JSON. Чтобы отдельно очистить комплектацию, удалите ключ `smart-house.configuration.v1` в хранилище сайта; серверные черновики удаляются как соответствующие JSON-файлы в `data/leads`.

Демонстрационный звук синтезируется браузером после действия пользователя. Во время просмотра внешние музыка, видео, шрифты, фотографии и текстуры не загружаются: необходимые карты материалов упакованы в GLB. Фотографии пользователя остаются локальными референсами проекта.

## Исходник и масштаб

Исходный `first.ifc` не перезаписывался. Его SHA-256:

```text
673317e4e4cc254a6f21e7e1336a80b5901b50a0d821d8cdde29f1164a2ef748
```

Маршрут: IFC2X3 → IfcOpenShell 0.9.0 / Python 3.13.11 → Blender 5.2.0 LTS → GLB → Meshopt. Нативные PLN/PLA, планы и перечень оборудования не предоставлены; работы в Archicad не выполнялись. Пользователь предоставил фотографию дома для уточнения экстерьера и фотографии образцов пола. Фасад, терраса и лестница используют отдельный приглушённый коричневый материал `Exterior timber | smoked brown` (ориентир sRGB `#756858`); внутренние материалы обновлены по новым образцам. Фотографии сохранены в `assets/reference`, не загружаются в браузер и напрямую на геометрию не накладываются.

В IFC найдено 611 объектов с сетками, 1 044 713 исходных треугольников, 0 `IfcSpace` и 0 внешних ссылок на текстуры. Есть записи этажей на 0 и 3 м; верхняя содержит кровлю и верхние элементы, поэтому интерфейс не выдумывает второй жилой этаж. Точные значения и исключения приведены в аудите.

Единицы IFC — миллиметры, геометрия после извлечения — метры. Контракт координат:

```text
Blender: (x − 8.29217, y + 3.72727, z)
glTF:    (x − 8.29217, z, −y − 3.72727)
```

Габарит оболочки стен приблизительно 8,110 × 6,610 м; пола с террасой — 8,002 × 9,500 м. Это измерения геометрии IFC, а не независимый обмер дома. Отдельный участок `IfcSite` и повторные тела-пустоты проёмов исключены из визуального экспорта. Полный предоставленный IFC остаётся у пользователя.

## Повторная подготовка геометрии

Для повторного экспорта нужны Python 3.13 с IfcOpenShell 0.9.0, Shapely 2.2.0 и Blender 5.2.0 LTS. В использованном колесе Shapely поставляется GEOS 3.14.1; версии и лицензии проверены по установленной среде в `docs/licenses.json`. Для веб-просмотра они не нужны. Скрипты запускаются из корня проекта. На другой ОС предварительно проверьте наличие совместимого колеса IfcOpenShell; исходный сеанс использовал macOS ARM64.

Перед ресурсоёмкой обработкой проверьте уже запущенные процессы и дождитесь окончания других сборок и тестов. При нагрузке Docker/OrbStack отдельно проверьте активные сборки, например `docker buildx history ls --filter status=running`. Не запускайте извлечение, Blender, оптимизацию и полный набор проверок одновременно.

Сначала сохраните рабочую копию предоставленного IFC, например в `source/first.ifc`; эта папка не публикуется веб-сервером. Исходный IFC в папку `public` помещать не нужно.

```sh
python3.13 -m venv .venv-ifc
.venv-ifc/bin/python -m pip install -r scripts/requirements-ifc.txt
.venv-ifc/bin/python scripts/extract_ifc.py source/first.ifc --output assets/ifc-geometry.json.gz
blender --background --python scripts/build_blender.py -- --project .
npx tsx scripts/optimize.ts
npm run validate:scene
```

Если `blender` не добавлен в `PATH`, на macOS вместо него используйте `/Applications/Blender.app/Contents/MacOS/Blender`. В Windows Python виртуальной среды находится в `.venv-ifc/Scripts/python.exe`.

`extract_ifc.py` читает IFC без записи, сохраняет контрольную сумму, применённые единицы и GUID. Затем он автоматически вызывает `prepare_roof_profiles.py`: Shapely объединяет проекции исходных треугольников двух проблемных стеновых слоёв, сохраняет проёмы и формирует `assets/roof-profile-repairs.json`. Кэш можно отдельно восстановить командой `.venv-ifc/bin/python scripts/prepare_roof_profiles.py assets/ifc-geometry.json.gz`; повторное извлечение IFC для этого не требуется.

`extract_ifc.py` также автоматически вызывает `prepare_interior_geometry.py`: он строит вертикальные доски с шагом 140 мм из точной проекции исходных слоёв вагонки и сохраняет проёмы. Кэш `assets/interior-lining-geometry.json` можно отдельно восстановить командой `.venv-ifc/bin/python scripts/prepare_interior_geometry.py assets/ifc-geometry.json.gz`.

`build_blender.py` воспроизводимо создаёт мастер, базовые текстуры, контрольный набор и реестр; затем готовит отдельные веб-ресурсы. Новые карты `Reference_oak_aya.png`, `Reference_smart_gris.png` и `Reference_whitewash_lining.png` должны оставаться в `assets/textures`: построитель читает готовые изображения и не вызывает генерацию изображений повторно. Исходные заменённые элементы сохраняются в мастере, упрощаются только копии статичной геометрии веб-профиля. Шторы и управляемые узлы остаются отдельными.

В извлечённой геометрии восемь слоёв стен выступали выше существующих скатов. В рабочей визуализационной копии они обрезаны по двум плоскостям кровли с закрытием торцов; шесть слоёв используют точное булево пересечение, два — восстановление исходного плоского профиля с сохранением отверстий. Размеры кровли, планировка и проёмы сохранены. Формула в мировых координатах IFC: `z ≤ 3.52983503 − tan(15°) × |x − 8.292172|`. Это явно зарегистрированное исправление визуализации; без нативного Archicad-проекта причина исходного CSG-результата окончательно не установлена.

В `master.blend` коллекция `Repaired_Architecture` содержит восемь рабочих исправленных слоёв. Скрытая в просмотре и рендере коллекция `Source_Untrimmed` содержит их копии до обрезки с именами `source_untrimmed_<GUID>`; эти копии исключены из GLB. Для сравнения отключите соответствующие рабочие объекты и включите коллекцию и объекты исходных копий. Не включайте обе версии одновременно: поверхности совпадают. Неизменённые `assets/source.ifc` и `assets/ifc-geometry.json.gz` сохраняются отдельно. Методы, связи копий, GUID и проверка закрытых сеток записаны в `docs/roof-envelope-repairs.json`.

**Повторный запуск построителя перезапишет генерируемые `assets/master.blend`, GLB, текстуры и отчёты.** Сохраните отдельно ручные художественные изменения в Blender; для воспроизводимости перенесите принятые решения в скрипт. Оптимизацию выполняйте после свежего экспорта Blender: она заменяет веб-GLB сжатыми версиями и сохраняет входные GLB в `assets/uncompressed`.

## Изменение и добавление устройств

Структура мастера содержит архитектуру, мебель, механизмы, свет, инженерные элементы и камеры. Имена узлов и `device.id` — контракт, а не автоматически назначаемые `Cube.001`.

1. Добавьте геометрию и постоянные имена в `scripts/build_blender.py`, назначьте комнату, категорию и независимые материалы изменяемых частей.
2. Добавьте или измените запись устройства в генераторе `public/scene-registry.json`: ID, систему, комнату, имена узлов, диапазоны, клипы и положение.
3. Обновите контракты `src/types.ts`, допустимую область устройств и команды в `src/state.ts`. Внутренние доли яркости, громкости, штор и клапана имеют диапазон 0…1.
4. Свяжите состояние с реальной геометрией в `src/scene/Scene.tsx`, добавьте элементы управления и понятные статусы в `src/App.tsx`.
5. Повторите экспорт, проверку реестра и нужные тесты. Визуально проверьте крайние и промежуточные положения, выключенное освещение и переходы камер.

Полотна используют морф `Open`: 0 — закрыто, 1 — собрано. В прикладном состоянии `devices.curtainsByRoom[room].current` имеет обратную семантику — долю закрытия; рендерер связывает их выражением `1 - current`. `devices.curtains` остаётся совместимым псевдонимом состояния гостиной. Команды `curtain` и `curtain-stop` принимают комнату либо `all`; без комнаты действует гостиная. Старые клипы `Curtains_Open_Left` / `Curtains_Open_Right` сохранены, дополнительные окна имеют отдельные постоянные имена и связи в реестре.

Вода хранит источник `leakActive` отдельно от фактического притока `inflow`. Команда `water-reset` возвращает только водную демонстрацию к сухому состоянию с открытым клапаном, сохраняя остальные устройства, конфигурацию и выбранный сценарий.

## Проверки и границы результата

```sh
npm test
npm run validate:scene
npm run build
```

После исправления протечки **35/35 тестов прошли**: 29 для состояния устройств и 6 для локального сервера. Добавлены регрессии повторного притока после раннего перекрытия/открытия, задержки датчика при повторном запуске, отдельного сброса воды, подтверждения охраны при водной аварии и старых снимков состояния. Новый экспорт с краном под мойкой, тканевыми шторами и изменённой мебелью прошёл Meshopt, проверки мастера/реестра/GLB и production-сборку. Первый фрагмент — **6 948 928 байт**, 138 130 треугольников, 68 узлов, 8 текстур; дом — **8 811 760 байт**, 199 873 треугольника, 82 узла, 9 текстур. Это данные ресурсов, не замер скорости загрузки.

В браузере осмотрены закрытая и собранная ткань панорамы и один прямой экран ТВ — снимки [38](docs/screenshots/38-fabric-panorama-closed.jpg), [39](docs/screenshots/39-fabric-panorama-open.jpg), [40](docs/screenshots/40-straight-tv.jpg). Условия и границы проверок приведены в [протоколе QA](docs/qa-report.md).

Действующие приводы дверей/окон, дополнительные умные системы спален и санузла и художественное согласование проекта не заявляются завершёнными.
